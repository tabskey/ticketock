## 步骤 / Steps
1. **Corrigir o refresh de sessão no frontend (maior prioridade)** — Em AuthContext.tsx: (a) signIn() chama queryClient.clear() em TODA renovação silenciosa, apagando o cache do React Query a cada ~1h e forçando refetch/loading flash; separar 'aplicar tokens' de 'login do usuário'. (b) O timer proativo e o handler reativo de 401 podem disparar refresh simultâneo com o mesmo refresh token single-use (rotacionado+revogado), causando 401 -> onUnauthorized -> logout indevido; serializar via uma única promise de refresh em voo (dedupe). Padrão atual em frontend/src/auth/AuthContext.tsx e frontend/src/api/client.ts.
2. **Reconciliar ADR 0006 com a implementação** — ADR 0006 decisão #3 diz 'row lock (SELECT ... FOR UPDATE)', mas o código usa UPDATE condicional com checagem de rowcount (ticket_repository.update_status). O ADR explicitamente descarta a abordagem que foi a implementada. Ou atualizar o texto do ADR para a abordagem real (UPDATE ... WHERE status = :expected), ou implementar o FOR UPDATE. Divergência documento-vs-código é dívida de contrato.
3. **Alinhar o enum de erros e a regra de resolution_note aos docs** — ARCHITECTURE §5 fixa o enum de code como {INVALID_STATUS_TRANSITION, TICKET_NOT_FOUND, UNAUTHORIZED, VALIDATION_ERROR, FORBIDDEN}, mas o código adiciona RESOLUTION_NOTE_REQUIRED, NOT_FOUND e HTTP_ERROR (core/errors.py, main.py). E a regra 'Resolved exige nota' não existe em ARCHITECTURE §4. Ou documentar ambos (ARCHITECTURE §4/§5 + ADR), ou remover. AGENTS exige 'no scope creep sem sinalizar'.
4. **Fechar a lacuna README/CI** — README e ARCHITECTURE §8 afirmam que a cobertura é 'enforced in CI' e referenciam .github/workflows/ci.yml, mas o workflow não existe (AGENTS item 9 aberto). Ajustar o texto para 'medida, não aplicada automaticamente' enquanto a CI não existir, ou de fato criar o workflow. Também revisar a linha do README que aponta para o arquivo inexistente.
5. **Rate limiting em /auth/login** — Sem limite de tentativas, o login fica exposto a brute-force; já reconhecido em ARCHITECTURE §10. Para protótipo, decidir explicitamente: implementar (ex.: slowapi/contador) ou registrar como risco aceito. Prioridade média.
6. **Harden do backend imagem/proxy** — backend/Dockerfile instala .[test] e copia tests/ para a imagem de produção, roda como root e sem --workers; atrás do Nginx falta --proxy-headers/--forwarded-allow-ips. Separar estágio de teste da imagem final, criar usuário não-root e adicionar proxy headers.
7. **Melhorar DX do Compose** — backend e frontend não têm healthcheck; nginx depende deles sem 'condition: service_healthy'; e o schema nasce vazio até alguém rodar alembic upgrade head manualmente (API responde 500). Adicionar healthcheck do backend, restart policies e avaliar entrypoint que aplique migrations no boot (ou manter manual mas documentar o footgun com destaque).
8. **Robustez do cliente de API do frontend** — parseResponse assume corpo JSON de erro; um 502/HTML do Nginx gera SyntaxError em vez de ApiError e cai no fallback genérico (em inglês, num UI PT-BR). Envolver o parse para produzir sempre ApiError.
9. **Robustez do backend (validação)** — get_current_user faz int(payload['sub']) e pode lançar ValueError -> 500 em vez de 401; password/title/description sem max_length (bcrypt>72 bytes, payloads grandes). Adicionar validação defensiva e limites.
10. **Verificar updated_at e o recurso de 'não lidos'** — useUnreadTickets depende de ticket.updated_at; change_status usa UPDATE em massa (query.update) — confirmar que o onupdate da coluna realmente dispara no bulk update via um teste, senão o badge de não lidos fica incorreto.
11. **Higiene de repositório e consistência de idioma** — (a) CODE_REVIEW.md está staged mas agora descreve problemas já corrigidos — atualizar/reescrever ou remover antes do commit. (b) .claude/ e design-reference/ untracked: gitignore ou remover. (c) AGENTS exige commits em inglês; commits recentes estão em PT ('adicionado testes', 'Ajuste finos'). (d) UI e fallbacks de erro em PT vs regra de 'código em inglês' do AGENTS — decidir e documentar a exceção se intencional.
12. **Rodar as suítes e validar** — Após as correções: docker compose exec backend pytest --cov=app --cov-fail-under=80 e docker compose --profile test run --rm frontend-test; confirmar gates >=80% e testes do AuthContext/client verdes.

## 风险与缓解 / Risks
- A corrida de refresh do frontend é dependente de timing (timer proativo vs retry reativo): pode não reproduzir de forma determinística e se manifestar só sob reload/tab em background. Validar com um teste que force refresh concorrente antes de considerar resolvido.
- Serializar o refresh altera AuthContext.tsx, que é amplamente testado — os testes existentes (AuthContext.test.tsx, client.test.ts) tendem a quebrar e precisam ser ajustados junto.
- Remover queryClient.clear() do caminho de refresh muda a semântica de troca de usuário (o clear existe para não vazar cache entre contas). Preservar o clear em login/logout reais e removê-lo apenas na renovação de token.
- Mudar textos do ADR/ARCHITECTURE para refletir o código pode mascarar a decisão original; preferir corrigir o código (FOR UPDATE) se a intenção era mesmo o lock, ou registrar explicitamente a mudança de decisão.
- Regex/keywords: verificar que onupdate de updated_at dispara em Query.update() — se não disparar, o recurso de não-lidos é o bug real, não o teste.
- Alterações de infra (não-root, healthcheck, migration no boot) podem quebrar o quickstart atual documentado no README; manter retrocompatível com o fluxo manual.

## Resumo do review (severidade atual)

Nada de severidade **Crítica** no estado atual — os itens críticos do CODE_REVIEW.md antigo já foram resolvidos pelo hardening (ADR 0006): segredo JWT passou a ser fail-fast (config.py sem default), httpx corrigido, deps fixadas, Dockerfile do frontend usando npm ci, tratamento reativo de 401, e transição de status ficou race-safe.

### Alto
1. **Corrida no refresh de sessão (frontend).** Timer proativo (`AuthContext.tsx`, ~30s antes do exp) e o retry reativo de 401 (`client.ts`) podem renovar em paralelo com o MESMO refresh token. Como o token é single-use (rotacionado + revogado no backend), um perdedor da corrida recebe 401 -> onUnauthorized -> signOut -> logout indevido. Não há dedupe de refresh em voo.

### Médio
2. **`queryClient.clear()` a cada renovação silenciosa.** `signIn()` é reutilizado pelo refresh e limpa TODO o cache do React Query — a cada ~1h o app descarta dados e refaz fetch (loading flash). Deveria separar 'aplicar tokens' de 'login real'.
3. **ADR 0006 diverge do código.** O ADR registra row lock (`SELECT ... FOR UPDATE`) e lista o UPDATE condicional como alternativa descartada — mas `ticket_repository.update_status` implementa exatamente o UPDATE condicional. O documento é o contrato; está errado.
4. **Lacuna README/CI.** README e ARCHITECTURE §8 afirmam gate de cobertura 'enforced in CI' e citam `.github/workflows/ci.yml`, que não existe (AGENTS item 9 aberto).
5. **Enum de erros + regra de negócio não documentados.** Códigos `RESOLUTION_NOTE_REQUIRED`, `NOT_FOUND`, `HTTP_ERROR` fora do enum fixo de ARCHITECTURE §5; a regra 'Resolved exige nota' não está em ARCHITECTURE §4 (scope creep não sinalizado).
6. **Imagem de produção do backend.** Instala `.[test]` e copia `tests/` para a imagem final, roda como root, uvicorn single-worker sem `--proxy-headers` atrás do Nginx.
7. **DX do Compose.** Sem healthcheck de backend/frontend, sem restart policy; schema nasce vazio até `alembic upgrade head` manual (API 500 em fresh up).
8. **Sem rate limiting no login** (já reconhecido em §10; brute-force).

### Baixo
9. `parseResponse` assume corpo JSON de erro — 502/HTML do Nginx vira SyntaxError e cai no fallback genérico em inglês num UI PT-BR.
10. `get_current_user` faz `int(payload['sub'])` -> 500 se malformado, em vez de 401; `password`/`title`/`description` sem max_length (bcrypt >72 bytes).
11. Verificar se `updated_at` (onupdate) dispara no `Query.update()` do change_status — o recurso de 'não lidos' depende disso.
12. Consistência: UI e mensagens em PT vs regra 'código em inglês' do AGENTS; commits recentes em PT (AGENTS exige inglês); `CODE_REVIEW.md` staged mas agora obsoleto; `.claude/` e `design-reference/` untracked.

### Positivos
- Layering respeitado: routers não tocam o DB direto; services não importam FastAPI.
- Autorização re-lê o usuário do banco (não confia no claim `role` do JWT) — evita escalonamento por token obsoleto.
- Transição de status race-safe via compare-and-swap (mesmo que o ADR descreva outra técnica) e coberta por teste de conflito.
- Envelope de erro consistente e casado com o contrato; testes co-localizados quase 1:1 com o código; segredo fail-fast e deps fixadas.
