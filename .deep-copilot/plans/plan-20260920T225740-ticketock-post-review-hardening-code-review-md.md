Each behaviour-changing fix ships with a test to keep the enforced 80% coverage gate green on backend and frontend. ## 风险与缓解 / Risks
- Fail-fast JWT secret (#1) breaks any environment without .env, including the README quickstart and the test suite — conftest and docs must change in the same pass or boot/tests fail.
- D1=B is the largest change: adding jti + a refresh_token table + rotation + revocation touches security.py, auth_service.py, api/auth.py, schemas, a new migration, ARCHITECTURE §5/§6/§10, ADR 0003, plus frontend logout and tests. Rotation without revoking the old token would not close the security concern the review raised.
- Two migrations land this pass (0006 indexes, 0007 refresh_token); the down_revision chain must be 0005 → 0006 → 0007 or alembic upgrade/downgrade round-trips break.
- Concurrency guard (#4): SELECT ... FOR UPDATE is hard to assert deterministically in tests; the conditional-UPDATE + rowcount variant is more testable. Choose deliberately and test the conflict path.
- Reactive 401 handling (#8) risks an infinite retry loop or a refresh/redirect race; the retry must be bounded to one attempt per request and must not fire for the refresh call itself.
- Pinning exact == versions (#9) can pin a version incompatible with current code; verify install + full test run after pinning.
- Coverage gate (80%) is enforced: new code paths (rotation, revocation, 401 retry, indexes) must ship with tests or the gate fails.
